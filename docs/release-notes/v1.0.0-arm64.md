# ProjectTenshin v1.0.0-arm64 — first release, verified on a Snapdragon 8 Gen 3 tablet

The first tagged release of ProjectTenshin, the native Linux ARM64 / Vulkan build
of the [doa3-re](https://github.com/NoRain211/doa3-re) static recompilation of
*Dead or Alive 3* (Xbox). It is ROM-free: you build the game binary yourself from
your own legally obtained disc.

## Verified on real hardware

Everything below was measured on one machine, not extrapolated: a Qualcomm
**Snapdragon 8 Gen 3** tablet (`qcom,sm8650-dpu`, detected as OnePlus Pad Pro)
running Linux 7.3.0 aarch64 with Mesa **Freedreno / Turnip** Vulkan
(`/usr/share/vulkan/icd.d/freedreno_icd.json`), SDL3 3.4.20, and 8 CPUs the
probe reports as `online=8 heterogeneous=1 prime=3 perf=6 silver=2`.

### The game runs, and holds 60 FPS

Built from a USA 3.0 disc (`default.xbe` sha256 `e523dd15…`, the build validates
it against the recorded program manifest `8e244632…`). The lifter translated
**6937 functions** with 83 hand-written overrides. Runner is a native
`ELF 64-bit LSB pie executable, ARM aarch64`.

- Default profile (`scale=1.00`, 720×480, 4:3): **59.97–60.11 FPS**,
  `frame_ms≈16.67`, worst frame 17.5–20.0 ms, 350–1070 draws/frame.
- Heavy profile (`RECOMP_D3D_SCALE=3`, `RECOMP_D3D_MSAA=2`,
  `RECOMP_D3D_WIDESCREEN=16:9`, fullscreen): presenter reports
  `resolution=2560x1440 msaa=2x depth=d24s8 a8=1 freedreno=1 water=modern`,
  and still **60.01 FPS** (`frame_ms≈16.67`, worst frame ≈18.4 ms).
- The attract mode and its CPU demo matches render fully: 3D stage geometry,
  characters, textures and effect passes all present.
- Exit is clean: `kind=normal-exit exit_code=0`.

### Audio

SDL3 output on PipeWire, 48 kHz stereo. Over one 4-minute run:
`submitted_buffers=87813`, `dropped_buffers=0`, `underruns=1`.

### The Vulkan path this build expects, probed on the device

`tenshin_vk_probe.aarch64` against the real Turnip driver:

- `BGRA8_UNORM` render target, `BC1`/`BC2`/`BC3` (DXT1/3/5), `A8_UNORM`: **OK**
- Depth `D24_UNORM_S8_UINT`, `D32_FLOAT_S8_UINT`, `D32_FLOAT` (water): **OK**
- MSAA **2× and 4×** on colour, D24S8 and D32S8: **OK** — MSAA **8×**: unsupported
  on this driver, so `RECOMP_D3D_MSAA=8` is correctly not offered here
- SPIR-V shaderc: **OK**; persistent on-disk shader cache populated

### Project test suites

- Python tooling and custody tests: **83 run, OK** (2 skipped)
- Host CTest suite: **50/50 passed** (1 skipped: `custom-music`)
- `tools/public_export.py verify --require-public-tree`: **passed**

## Not verified

- **No manual input.** The device's `/dev/uinput` is root-only and no input
  injection helper was installed, so gameplay was observed through the game's own
  attract mode and CPU demo matches, not through a player pressing buttons.
  Controller and keyboard paths are covered by the host CTest suite only.
- The Europe 3.2 disc remains in bring-up upstream; this release was tested with
  USA 3.0 only.

## Contents (zero game files, zero ROM-derived code)

The attached archive is the ROM-free distributable, as described in the notes
tail below. Your own `doa3.aarch64` is built locally by
`tools/build-arm64-game.sh /path/to/doa3.iso` and is never distributed.
